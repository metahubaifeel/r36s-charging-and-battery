# R36S 充电灯一直亮、电量却不涨 —— 充电、电池与待机耗电

**[English](README.md)** · **中文**

> **一句话结论。** R36S 只有一个充电口：主板上丝印为 **DC** 的那个，规格 **5 V / 2 A（最大）**。如果你用的是 **USB-C 转 USB-C** 的线配 PD 快充头，换成 **USB-A 转 USB-C** 的线 + 普通 5 V 充电头——这一条就是"灯亮着、电量不涨"最常见的解药。那个指示灯**不是电量表**：我们自己手上的机器，同一个灯位跑起来是绿的、插着线是红的、还有一台是紫的。**看屏幕上的百分比，别看灯。**
>
> **"快充头会不会把功放芯片搞坏"这个问题，目前没有定论。** 我们查了，查不到，所以不装作查到了——见 [§ 快充头到底危险吗](#快充头到底危险吗诚实的回答没有定论)。
>
> **待机掉电是真的，但那不是故障。** 这个平台没有真正的待机。关机放着一晚上掉得很少；停在菜单界面、或者游戏里暂停着又开着 WiFi，第二天早上一定是空的。

## 为什么会这样

### 1. 有两个口，而且它们不能互换

机器底部边缘并排有两个接口，主板丝印分别是 **OTG** 和 **DC**：OTG 是数据口（USB 网卡插这里），DC 是充电输入，规格 5 V / 2 A。

关于"哪一边"有两件事值得分开讲，因为网上的混乱就出在这里：

- **站上的规格书写的是"左侧 DC 口"**，供应商的说法也是同一句话：左边那个是 DC。
- **主板丝印标的是 `OTG` 和 `DC` 两个标记**，我们手里样品板上的这两个标记分布在这对接口的两侧。至于哪个标记物理上在左，取决于你是从机器正面看、还是拆开后盖看主板（这是一个镜像关系）——**我们没有把每个批次都验证到，所以不装作已经解决。**

所以真正站得住的用法，就是站上 FAQ 里那句：**找到标着 DC 的那个口，以你机器上的标记为准，不要相信"左边"这两个字。**

![V30 样品主板底部：丝印为 OTG 与 DC 的两个接口，以及电池插头](docs/05-v30-board-dc-otg-battery-plug.jpg)

*我们自己货源的一块 V30 样品主板。底部两个接口分别丝印 `OTG` 与 `DC`；中间那根红黑绞线是电池插头。供应商样品实拍，未做修饰。*

**插错口是一个真实嫌疑。** 上表第一条就是这种情况的典型描述：灯亮着、什么都不发生，而且换线和换头都没用——因为问题和线和头都无关。

> ⚠️ 未实测：把充电头插在 **OTG** 口会不会让灯亮着而电池不充，我们**没有实测**。我们手上确实有一张"两个口同时插着线"的真机照片——这正是这类误会的起点。所以请把"换另一个口试试"当成一个两秒钟的免费尝试，而不是一个诊断结论。

> ⚠️ 未逐批验证：每个批次上哪个标记对应哪个接口，以及接口本身是什么类型。我们的证据是自己样品板上的丝印，加上自己拍的照片——照片里两个口插的是同一种插头外壳。请以你机器上的 `DC` 标记为准，站上 FAQ 也是这么写的，原因相同。

### 2. USB-C 转 USB-C 配 PD 充电头，输出可能是 0 V

这是 USB-C 规范层面的后果，不是 R36S 独有的怪毛病。

USB-C 电源只有在 CC 线上检测到正确的下拉电阻（Rd，标称 5.1 kΩ）之后，才会把 5 V 加到 VBUS 上。**一个外形是 USB-C、但没有 CC 电阻的设备，在 modern USB-C 电源看来就等于"什么都没插"。** 而 USB-A 口没有这套握手，它只是老老实实输出 5 V —— 这就是为什么 A 转 C 的线能用、C 转 C 的线不能用。

实际后果值得直接写出来：

| 电源 | 线 | 预期结果 |
|---|---|---|
| 普通 5 V / 1 A 或 5 V / 2 A USB-A 充电头 | USB-A → USB-C | 纯 5 V 输出、无需协商，也就是我们规格书描述的那种配置 |
| 笔记本 USB-C 充电头（PD） | USB-C → USB-C | 电源看不到协商，可能一直停在 0 V |
| 充电宝的 USB-A 口 | USB-A → USB-C | 正常 |
| 只有 USB-C 口的充电宝 | USB-C → USB-C | 同样的 0 V 问题 |

> ⚠️ 未实测：我们没有拿表去逐个组合测 VBUS，CC 电阻这套解释属于工程背景，不是我们自己的实测数据。我们把它放在第一条，是因为它免费、可逆，而且其他社区的独立文章也这么讲——不是因为我们有台架数据。

### 3. 会"自动关口"的充电头和充电宝

多口充电头和充电宝通常在负载低于某个阈值（常常是几十毫安）时把这一路断掉。一台快充满的机器，或者处在低功耗涓流状态的机器，就可能掉到这个阈值以下。口一断，机器就看不到供电，症状正好就是群友描述的那样：灯亮着、电量不动。换单口充电头，或者换多口头上的另一路试试。

### 4. 线本身

只有充电线芯的线（没有数据线）、磨损的线、线径太细的线，都撑不住机器想拉的电流。本文里最便宜的一个诊断就是：**把同一根线、同一个充电头插到手机上，看手机能不能正常速度充电。** 如果手机也不行，问题已经找到了，完全不用碰掌机。

### 5. 电池被放到很深

如果电池长时间处于放空状态，电池保护板可能已经切断了输出，机器在电源上需要很久才有可见变化。先在一个确认正常的 5 V / 1 A 或 2 A 电源上放两小时，再下结论。

### 6. 剩下的才在机器里面

如果确认正常的电源 + 确认正常的线、插在 **DC** 口上，30–60 分钟内百分比一动不动，那剩下的可能性是充电电路、接口焊点，或者电芯。这时候该做的不是再换一个充电头，而是**联系卖家**。从我们这里买的机器有 7 天无理由退货，也有邮件 / Discord 支持——拆壳或换电芯之前先问我们。

### 快充头到底危险吗？诚实的回答：没有定论

群友那句是**提问**，不是事故报告：`是不是用快充头充电是不是有概率会把功放芯片整坏？`

能说的和不能说的，分开讲。

**属于工程事实的部分。** 合规的 USB 充电器不会"灌"功率。它标的瓦数是它**能提供**的上限，不是它**强加**的电压。Power Delivery 只有在和设备完成显式协商之后才会把电压抬到 5 V 以上。一台从不协商的设备，从合规电源那里永远拿不到 5 V 以上。所以"65 W 的头会把 65 W 硬塞进 5 V / 2 A 的掌机"这种说法，在硬件层面不成立。

**我们查不到的部分。** 我们**没有找到任何经过验证的失效分析**，能把快充头和 R36S 功放芯片损坏联系起来——没有拆解、没有测量、没有可复现的案例。流传的是一个被反复问的问题。而这个平台上确实存在一个和充电头无关、且真实存在的功放相关现象：**WiFi 版有轻微喇叭底噪**，这一点站上产品页已经如实披露，我们也是因此把它作为 WiFi 选项的取舍写出来，而不是当成故障。

**所以：故意不下结论。** 如果你想选风险最小的做法，那也正好是最便宜的做法：USB-A 的 5 V / 1 A 或 5 V / 2 A 充电头 + A 转 C 线。不是因为我们证明了快充头会弄坏东西，而是因为这台机器用不上更多，多出来的部分全是纯风险。**请不要把这条建议读成"我们承认快充头会造成损坏"——两种情况我们都没有证据。**

### "放一晚上就没电" —— 是系统没关机，还是硬件漏电？

**机制一，也是最常见的原因：这个平台没有真正的待机。** 群友的说法是 `开源是没待机`，这和平台事实对得上：一台跑着普通 Linux + 前端程序的掌机，没有手机那种 suspend-to-RAM 加硬件唤醒路径。这类系统的电源控制一般接到"关机"，而不是"睡眠"。如果你把它停在菜单界面，或者在跑着的游戏里暂停着——SoC 还在跑、背光还亮着，WiFi 开着的话射频也还在工作。这样放一晚上，就是一晚上满载待机的耗电。

> ⚠️ 未实测：我们**没有**用仪表测过各状态下的电流，也**没有**在三个版本上验证电源控制的映射关系。上面描述的是平台和群里反映的行为；真正能依赖的是下面的**测试**——因为它测的是你自己那台机器。

所以诚实的测试分两步，中间隔一夜：

1. **正常关机**（菜单里退出/关机，不是只拨一下开关、也不是合上就走），确认屏幕全黑、指示灯灭。然后放 12 小时。
2. **开机看百分比。** 健康的机器在完全关机状态下能保住绝大部分电量。**如果关机后指示灯还亮着，那就是没真正关机**——这就是机制一，机器没坏。

即便是正确关机的机器，也会有少量静态耗电和正常的电芯自放电，所以"放一晚上掉几个点"本身不算故障。**掉空**才算。

**机制二：电芯老了。** 上文那条群消息就是最好的证据 —— `用了两年多电池剩80多不太耐电了`（用了两年多，健康度剩八十多，不太耐电了）。电芯会老化。如果一台以前能撑四小时的机器现在只撑两小时，换线、换头、刷固件都救不了。

## 续航到底该期待多少？

| 说法 | 来源 | 状态 |
|---|---|---|
| GBA 这类游戏大约 4–5 小时 | QQ 群，反复出现 | 社区反映，**不是**我们的实测 |
| "便携最少要能有 4-5 小时续航" | QQ 群，作为要求提出 | 社区预期 |
| 标称 4–6 小时 | 电商平台宣传页 | 厂商 / 平台宣传口径 |
| 5 V / 2 A 充电头从空到满约 2–3 小时 | 社区文章 | ⚠️ 我们**没有**掐表测过 |

电池容量这件事，我们选择把自己的底单摆出来，而不是给一个干净漂亮的数字，**因为我们自己的记录本身就互相矛盾**：

| 数字 | 出处 |
|---|---|
| 3.7 V、3000 mAh、11.1 Wh，电芯标记 **JLCL 804069P** | 我们的电芯溯源记录 |
| 3200 mAh | 我们的国际物流资料（按 UN3481 内置锂电池申报） |
| 3200–3500 mAh | 公开电商平台的商品页 |
| **约 11 Wh** | 以上所有说法唯一能对上的量级 |

> ⚠️ 未实测：我们没有把三个版本的机器都拆开读电芯铭牌，所以**不把任何一个容量数字当事实发布**。把电池当成大约 11 Wh 来看，续航以你自己实测为准。

对续航影响最大、而且都免费的两件事：**屏幕亮度**和**你在跑什么**。8 位 / 16 位机很省电；PS1、N64、Dreamcast 很费电。WiFi 开着也要钱。

## 怎么修

从上往下走，**在哪一行让屏幕上的百分比动了，就停在哪一行**。

![充电排查清单](docs/06-charging-checklist.png)

1. **插对端口。** 用主板标记为 **DC** 的那个口。如果没反应，*也顺手试一下另一个口* —— 不花钱，而且这两个口真的很容易搞混。
2. **如果你原来用的是 C 转 C，换成 USB-A 转 USB-C。** 这是收益最高的一步。
3. **用普通的 5 V / 1 A 或 5 V / 2 A 充电头**，有单口的就用单口，避开充电宝上"只有 USB-C"的那个口。
4. **把线插到手机上试。** 手机也充得慢或者充不进，到此为止——问题已经找到了。
5. **没电的机器先给它 30–60 分钟。** 不要两分钟拔一次、插一次——那样你分不清涓流和没电流。
6. **有工具就测。** 在充电头和线之间串一个 USB 电流表，立刻就知道真相：正常充电会同时有电压**和**电流。注意要在电量不满的时候测，满电时电流自然接近零。
7. **用正确的方法看百分比。** 官方系统和供应商系统的界面上都有电量数字（见下面的照片）。记下来，**关机**充一小时，再开机对比。动了，说明充电路径是好的，原来的问题出在电源或线上。
8. **只有到这一步才怀疑机器。** 确认正常的电源 + 确认正常的线 + 正确的端口 + 一小时 + 百分比不动 = 联系卖家。

### 如果你想在命令行里看

这是 Linux 标准的电源接口。在机器上跑（基于 ArkOS 的系统就是 Linux，所以可能可用）：

```bash
ls /sys/class/power_supply/
```

在普通 Linux 笔记本上，它会输出类似：

```
ADP0  BAT0  ucsi-source-psy-USBC000:001
```

然后，如果存在电池节点：

```bash
cat /sys/class/power_supply/BAT0/capacity
cat /sys/class/power_supply/BAT0/status
```

> ⚠️ **在 R36S 上未实测。** 我们**没有**验证过 R36S 上的 ArkOS 会不会暴露名为 `BAT0` 的 `power_supply` 电池节点；用厂商内核的机器上，这个节点可能根本不存在，或者换个名字。上面那段输出来自一台**普通 Linux 笔记本**，不是 R36S。如果 `ls` 没有任何输出，就改用屏幕上的百分比——我们就是这么做的。

## 怎么验证修好了

只有**数字动了**才算修好：

1. 读屏幕上的电量百分比。愿意的话拍张照——省得后面扯皮。
2. 关机，用你的 A 转 C 线接到 **DC** 口，配一个 5 V 充电头。
3. 放着别动，一小时，机器处于关机状态。
4. 开机，再读一次百分比。

涨了几个点，说明充电路径是好的，原来的问题在电源或线上。用一根已经在手机上验证过的电源仍然不涨，说明故障在机器内部。

待机这一项，验证要花一晚：**正确关机**、确认指示灯灭、放 12 小时、开机。**关机后指示灯还亮，说明它根本没关机**，那这就是你掉电的原因。

- 正常：在 **DC** 口上百分比上升；关机后指示灯灭；关机放一晚能保住电。
- 不正常：一小时之后百分比纹丝不动（见 [§ 怎么修](#怎么修)）；关机后指示灯还亮（没真正关机）；**关机**放一晚就空（电芯或主板问题——找卖家）。

## 怎么别再踩

- **把充电这套东西固定下来。** 给这台掌机留一个固定的 USB-A 5 V 充电头和一根 A 转 C 线，就这一套。上面那些群消息里的翻车，几乎都是"用了个充手机没问题的头，但充不了这台机器"。
- **插在你确认过是 DC 的那个口上**，并且以标记为准，而不是以"左边"为准——"左边"取决于你怎么拿着它。
- **包装里没有充电线。** 站上产品页写得很明确。请**和掌机一起**买一根 USB-A 转 USB-C 的线，而不是等第一次电池空了再买。
- **不用了就关机。** 每次都走菜单里的关机，否则就接受第二天早上是空电。如果你主要玩短时段，这是收益最大的一个习惯。
- **不用 WiFi 的时候就关掉**——买之前也请看清披露：WiFi 版有轻微喇叭底噪，而且关掉 USB 或网络相关设置之后，可能需要重刷系统才能把 WiFi 恢复回来。
- **看百分比，不要看颜色。** 本文开头那张表里的每一次虚惊，都是有人在读一个 LED。
- **别想靠换大电池来解决充电故障。** 如果口、线或电源不对，换更大的电池什么也解决不了。而"电芯老化"只有在做完上面第 1–4 步之后才是一个成立的判断。

## 哪些是实测的，哪些不是

这一段通常会被跳过，所以我们单独列出来：

| 本文中的说法 | 依据 |
|---|---|
| 充电输入最大 5 V / 2 A，走标记为 DC 的口 | 站上自己的产品规格 + 供应商说法；照片里主板丝印确实是 `OTG` 与 `DC` |
| 底部有两个口，且二者不能互换 | 主板丝印 + 我们自己拍的"两个口都插着线"的真机照片 |
| 两个口插的是同一种插头外壳 | **我们自己的照片**。⚠️ 没有逐批确认接口类型——请以你机器上的 `DC` 标记为准 |
| 指示灯充电时红、运行时绿 | **我们自己的真机照片**（见上） |
| 指示灯不是有文档的电量表；我们有一张照片是紫的 | **我们自己的照片**；"没有文档"这一条是通过"找不到任何颜色对照表"验证的 |
| 3000 mAh 与 3200 mAh 的矛盾 | **我们自己的内部记录互相矛盾**——我们把矛盾写出来，而不是挑一个数字 |
| C 转 C 接 PD 电源可能输出 0 V | USB-C 规范行为，加上其他社区独立文章的印证。⚠️ **不是**我们台架测出来的 |
| 快充头会损坏功放芯片 | ⚠️ **两个方向都没有找到经过验证的案例。** 不作结论 |
| 充满 2–3 小时、续航 4–6 小时 | ⚠️ 第三方说法，**不是**我们掐表测的 |
| R36S 上存在 `power_supply` 节点 | ⚠️ **未验证。** 示例输出来自一台普通 Linux 笔记本 |
